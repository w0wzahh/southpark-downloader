# Security policy

## Reporting a vulnerability

Please do not open a public issue for a security vulnerability.

Use GitHub's private security advisory feature for this repository once it is published, or contact the maintainer privately through the contact method listed on the repository profile.

When reporting a vulnerability, include:

- affected version;
- reproduction steps;
- impact;
- a minimal proof of concept where safe to provide.

Do not include passwords, cookies, access tokens, signed media URLs, or other private credentials.

## Scope

This project does not intentionally bypass DRM or other access controls. Reports involving ordinary application security, unsafe file handling, dependency vulnerabilities, or accidental credential exposure are welcome.
